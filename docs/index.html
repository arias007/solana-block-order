Solana Block Order Explorer

Paste any slot. See whether the leader ordered that block by priority fee — or by something else.

What this measures

Why priority fee does not equal position

Every block explorer shows you the fee you paid. None of them show you whether paying more actually put you earlier in the block.

This tool fetches the full block, strips vote transactions, and computes the Spearman rank correlation between a transaction's index in the block and two things: its priority fee, and its compute units consumed.

If blocks were fee-sorted, the fee correlation would be strongly positive. Across the validators measured so far, it is not — the correlation sits near zero and even flips sign between clients. What does track position, weakly, is compute: longer transactions land later, which is the fingerprint of a parallel scheduler writing out transactions in completion order.

How the numbers are computed

Priority fee = meta.fee − 5000 × number of signatures. The 5000 lamport base fee per signature is subtracted so only the priority component remains.

Price = priority fee ÷ compute units consumed.

ρ is Spearman's rank correlation over the block's non-vote transactions, so it is insensitive to the huge spread in fee magnitudes (a few transactions pay 1000× the median).

Saturation = total compute units ÷ 48,000,000, the per-block compute limit. A block above ~70% is where fee-ordering would matter most if it existed.

Vote transactions are excluded

Vote transactions occur in fixed positions at predictable intervals and would dominate any correlation. They are identified by the presence of the Vote program account and removed before analysis.
